# Парето + SMAA по сохранённым результатам

Необязательный анализ чувствительности к предпочтениям **без референсных
соединений**. Докинг и ADMET не запускаются повторно. Пункт **15** меню и
`--pareto-run` сохраняют прежний режим «только Парето». Пункт **16** или
`--smaa-menu` предлагает два отдельных действия: создать шаблон шкал и выполнить
«Парето + SMAA» либо «только SMAA». HTML создаётся автоматически; GUI не требуется.

Это адаптация SMAA-2 с фиксированными значениями свойств и изменяющимися весами.
Доли сценариев **не являются вероятностью экспериментального успеха,
клинической безопасности или истинного превосходства**. Docking score не равен
измеренной активности, а выход ADMET-классификатора — индивидуальной точности
предсказания. Модель ошибок свойств не предполагается.

## Запуск

Команды выполняются из основной папки DockScreen с Python окружения докинга.
В Windows замените `python` на `.\.venv\Scripts\python.exe`, если окружение не активировано.
`RUN` — завершённый запуск внутри `output/runs`, `TARGET` — точный ID мишени.
Используйте уже отредактированный CSV Парето; его формат не меняется.

```powershell
python main.py --smaa-template RUN --pareto-criteria settings/PARETO_CRITERIA.csv --smaa-settings SMAA_SETTINGS.json --pareto-target TARGET
# Проверьте и при необходимости отредактируйте SMAA_SETTINGS.json.
python main.py --smaa-run RUN --pareto-criteria settings/PARETO_CRITERIA.csv --smaa-settings SMAA_SETTINGS.json --pareto-target TARGET
```

Для неоднозначной мишени обязателен `--pareto-protocol` с точным ID протокола.
Шаблон показывает protocol_id; номера/ID также доступны в терминальном меню.
Существующий файл настроек никогда не перезаписывается созданием шаблона.
Шаблон не выполняет сценарии и не создаёт успешный анализ.
CLI `--smaa-run` поддерживает `--export-zip result.zip`; существующий ZIP требует
явного `--overwrite-zip`. Текущий пункт экспорта ZIP также включает завершённые
SMAA-результаты выбранного запуска при включении отчётов.

Старые запуски без preparation.json сначала нужно явно адаптировать существующим
механизмом импорта сохранённого запуска. SMAA сам такую адаптацию не выполняет.

## Критерии, шкалы и веса

CSV определяет включённые цели, направления и ограничения. Границы включительные,
пропуск/нечисловое/неуспешный докинг исключают строку с причиной, как в Парето.
В анализ входят **все допустимые строки, в том числе доминируемые**, а не только
фронт. Названия могут повторяться: идентичность определяется стабильным ID строки.
Без целей SMAA завершается ошибкой; отбор только по ограничениям остаётся в Парето.

Отдельный JSON фиксирует `scales` в порядке целей CSV:

| Поле | Смысл |
|---|---|
| key, direction | ID и направление из CSV; должны совпадать |
| worst | Значение низкой желательности, utility=0 |
| best | Значение высокой желательности, utility=1 |
| alpha | Параметр Dirichlet для веса этой цели, от 0.01 до 100 |
| low, high | Только range: целевой интервал из CSV |
| origin | Зафиксированное происхождение автоматических границ |

Для `max` должно быть best>worst, для `min` — best<worst.
Между якорями желательность линейна: `(x-worst)/(best-worst)`, за границами
насыщается до 0 или 1. Для `range` сначала вычисляется расстояние
`max(low-x, 0, x-high)`, затем уменьшается желательность при росте расстояния:
best=0, worst>0, оба в исходных единицах расстояния.

Автоматический шаблон использует конечные значения каждой цели для выбранного
протокола **до CSV-ограничений**, включая строки, не прошедшие другие критерии.
Для min/max это наблюдаемые min/max, с соответствующим направлением.
Если все значения равны x, границы расширяются на ±max(|x|×0.01, 0.5),
так что исходное постоянное значение получает желательность 0.5.
Для range best=0, worst=максимальное наблюдаемое расстояние; если оно равно 0,
worst=1 исходная единица расстояния. Отсутствие конечных данных для цели — ошибка
создания шаблона, требующая пересмотра доступных целей.

Это **исследовательский способ нормирования**, а не биологические нормативы.
Проверьте якоря и задайте содержательные границы вручную, когда они известны.
При выполнении используется точный JSON; границы незаметно не пересчитываются.
Хэши привязывают его к CSV, источникам и протоколу. После изменения CSV создайте
новый файл шаблона, осознанно сохранив прежние worst/best/alpha, если хотите
сравнить только влияние ограничений. Новый шаблон заново наблюдает границы;
такое сравнение требует проверки совпадения якорей. Фильтрации отображения нет.

Аддитивная ценность — сумма `weight_i × utility_i`. Веса означают trade-off
между полными переходами от worst к best; это не только абстрактная «важность».
Внутри допустимого набора модель допускает компенсацию одного свойства другим.
Пересекающиеся/коррелирующие endpoints не являются независимыми свидетельствами
и могут усиливать общий сигнал при включении в несколько целей.

Настройки `sampling`: iterations (по умолчанию 10000), seed (42), top_n (10),
batch_size (64), rank_quantiles ([0.05,0.95]), weight_distribution (`Dirichlet`).
Распределение весов генерируется настоящим `Generator.dirichlet` с PCG64.
Все alpha=1 дают равномерное распределение **по симплексу** — выбранное допущение,
зависящее от состава целей и шкал. Независимые uniform с нормировкой не используются.
Средний вес равен alpha_i/sum(alpha); изменение alpha задаёт другие предпочтения.

## Ранги и равенства

Сравнивается итоговая float64-ценность при фиксированном порядке суммирования целей.
Равенство точное, без допуска; близкие, но разные числа остаются различными.
Группа из k равных кандидатов на местах a…b получает по 1/k доли каждого
занятого места для каждого участника. Если топ-N пересекает группу, доля попадания
равна числу её мест внутри топ-N, делённому на k. Например, три равных кандидата
при топ-1 получают по 1/3. Порядок исходных строк не даёт преимущества.
Это симметричное расширение классического SMAA-2, а не правило общего ранга
«1 + число строго лучших».

На каждом месте сумма долей по кандидатам равна 1; распределение каждого
кандидата также суммируется до 1 (с численной погрешностью). Нулевые элементы
разреженного распределения не записываются. Ожидаемый ранг — среднее по этому
распределению; медиана и квантили — обратная дискретная CDF (первый ранг, где
накопленная доля достигает q), не интерполяция.
При top_n больше допустимого набора применяется min(top_n, count), оба числа
сохраняются. Исключённые строки не получают последний ранг или нулевое качество:
их SMAA-метрики — null в JSON и пустые ячейки CSV.

Clipping может превратить строгую исходную Парето-доминацию в равенство
желательностей; поэтому доминируемая строка иногда может разделить первое место.
Статус Парето сохраняется по исходным показателям CSV.

## Выходные файлы и воспроизводимость

Каждый запуск создаёт новую `RUN/smaa/analysis-<uuid>/`:

- `criteria.csv`, `settings.json` — точные байты использованных настроек.
- `metadata.json` — версии метода/программы/Python/NumPy, seed, сценарии, PCG64,
  распределение/alpha, шкалы/их происхождение, ограничения, протокол и хэши.
- `results.json` — все исходные строки, ID, название, SMILES, выбранные значения,
  статус Парето, причины исключения и SMAA-метрики/распределения.
- `candidates.csv` — краткие метрики: доли первого места и топ-N, ожидаемый и
  медианный ранг, выбранные квантили и стандартная Monte Carlo погрешность долей.
- `rank_acceptability.csv` — разреженное распределение мест: ID, rank,
  acceptability_fraction (доля от 0 до 1, не процент).
- `SUMMARY.txt`, `status.json` — текстовый итог и признак завершения.

CSV защищён от spreadsheet formulas; исходные строки неизменны в JSON. Поле
`central_first_weights` — условное среднее весов с дробным вкладом первого места,
описательная характеристика, не confidence factor классического SMAA.
MC standard error оценивает интегрирование **выбранных предпочтений**, не
неопределённость ADMET. Нулевая MC-погрешность не означает научную достоверность.

Источники проверяются до/после чтения и перед публикацией: preparation.json,
results.json, summary.json, admet.json, task_outcomes.json, включая отсутствие
необязательного файла. Изменение источника прерывает публикацию.
Повторяемость требует одинаковых входов, порядка целей, конфигурации и версий;
межплатформенное побитовое совпадение не обещается. Временная метка и UUID папки
естественно различаются, а численные результаты при одинаковой среде повторяются.

Прогресс выводится пакетами; Ctrl+C прерывает выполнение. Незавершённые файлы
остаются только в `.incomplete-*` с failed/cancelled, если сохранение уже началось;
ошибка до сохранения не создаёт папку. Только полностью записанная папка получает
имя analysis-* и complete; ZIP не включает временные/незавершённые анализы.
При пустом допустимом наборе сохраняется корректный пустой итог и все причины
исключения. Предсказания и докинг никогда не пересчитываются, границы не ослабляются.

Технические лимиты: до **100000 исходных строк**, 64 целей, 100000 сценариев,
batch_size от 1 до 256, seed от 0 до 4294967295. Для больших библиотек потребуется
отдельная реализация. Оценка памяти ядра ограничена 256 MiB, это не жёсткий
предел RSS процесса: объекты Парето, JSON и Python увеличивают расход памяти.
Матрицы сценариев пакетные; вся история сценариев не сохраняется. Распределения
рангов имеют худшую сложность памяти O(n²); длинный CSV пишется потоком.

## Источники метода

[Lahdelma & Salminen, SMAA-2 (2001)](https://doi.org/10.1287/opre.49.3.444.11220),
[Tervonen & Lahdelma, Implementing SMAA (2007)](https://doi.org/10.1016/j.ejor.2005.12.037),
[авторское изложение SMAA](https://research.ics.aalto.fi/events/AKRR05/papers/akrr05tervonen.pdf).
Независимое научное ревью реализации не заменяет внешней валидации молекулярных
предсказаний и модели предпочтений на вашей задаче.

Предел в 100000 исходных строк не гарантирует ранжирование стольких допустимых кандидатов.
Проверка памяти SMAA остаётся отдельной: текущая плотная матрица рангов имеет
размер O(n²) по числу прошедших ограничения. Если её оценка превышает 256MiB,
расчёт отклоняется до выделения матрицы; сократите допустимый набор критериями.
Лимиты размера CSV и числа пар молекула–мишень сохраняются.

Автоматические HTML и схема имён документов описаны в [основном руководстве](../README_RU.md#html-и-понятные-имена-документов).

Полные библиографические записи SMAA-2 и его вычислительной реализации приведены
в [общем списке научных источников](references.md#optional-admet-and-preference-analysis).
Там же перечислены ADMET-AI, Chemprop, PyTorch и TDC, если в анализе использовались
их предсказания. Публикации описывают исходные методы; допущения именно DockScreen
и правило равных рангов определены в этом руководстве.

При разделении библиотеки на отдельные SMAA-анализы меняется набор сравниваемых
альтернатив. Ранги и доли топ-N из таких анализов нельзя просто объединить в общий
рейтинг. Разделять независимые задачи докинга допустимо; для общего анализа
предпочтений нужен согласованный набор кандидатов и одинаковые шкалы.
