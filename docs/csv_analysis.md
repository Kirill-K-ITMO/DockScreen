# ADMET, Парето и SMAA из CSV-отчёта DockScreen

Пункт **17** основного меню принимает CSV, созданный обычным отчётом DockScreen,
включая отчёты с ADMET. Выберите один из режимов:

- ADMET: локальные прогнозы и обычный отчёт HTML/CSV с выбором ADMET-столбцов.
- ADMET + Парето: дополнительно отбор через CSV критериев.
- ADMET + Парето + SMAA: дополнительно распределения рангов по предпочтениям.
- ADMET + SMAA: анализ предпочтений без отдельного отчёта Парето; ограничения CSV продолжают применяться.

Исходный файл и существующие результаты не перезаписываются. Создаётся отдельный
`output/runs/csv-import-<uuid>/`. Докинг и подготовка конформеров не запускаются.
SMILES из CSV используются для локального ADMET с обычной политикой проверки
структур и кэширования. Старые ADMET-числа из CSV игнорируются: без проверенных
исходных метаданных они не заменяют локальные предсказания. Ki/pKi не импортируются
как экспериментальные данные; при создании обычного отчёта они вновь выводятся как
оценки, полученные из docking score, с прежними ограничениями интерпретации.

## Терминальный запуск

```powershell
python main.py --csv-analyze report.csv --admet-python .venv-admet/Scripts/python.exe --csv-analysis-mode pareto+smaa --pareto-target JAK2_6BBV
```

Для одного рецептора мишень можно не указывать; для нескольких необходим явный
выбор `--pareto-target`. Оценки разных мишеней не смешиваются. Режим задаётся через
`--csv-analysis-mode admet`, `pareto`, `smaa` либо `pareto+smaa` (последний — по умолчанию).
Для собственных ограничений передайте `--pareto-criteria MY_CRITERIA.csv`.
Без него используются текущие пять критериев user-default-v3: docking≤−7,
DILI≤0.5, ClinTox≤0.5, Bioavailability_Ma≥0.5, hERG≤0.5, с прежними направлениями.
Равенство границе проходит; пропуски активных показателей исключают строку.
Пустой набор сохраняется без ослабления ограничений.

Можно добавить `--export-zip result.zip` (путь вне защищённых папок исходников и
выбранного запуска), `--admet-batch-size` и `--admet-timeout`. При ошибке ADMET
импорт и доступные прогнозы остаются в напечатанной папке; успешный SMAA не
объявляется. Отдельные невалидные молекулы получают причины исключения.

Автоматический SMAA сохраняет `SMAA_SETTINGS.json`: закреплённые наблюдаемые
шкалы выбранного протокола до ограничений, Dirichlet(alpha=1), 10000 сценариев,
seed=42, top-N=10. Эти допущения объявляются перед выполнением. Для ручной
проверки шкал до расчёта предпочтений сначала выполните только импорт:

```powershell
python main.py --csv-import report.csv
# Подставьте напечатанный RUN: output/runs/csv-import-...
python main.py --admet-run RUN --admet-python .venv-admet/Scripts/python.exe
python main.py --pareto-template RUN --pareto-criteria MY_CRITERIA.csv
python main.py --smaa-template RUN --pareto-criteria MY_CRITERIA.csv --smaa-settings MY_SCALES.json --pareto-target JAK2_6BBV
# Отредактируйте MY_SCALES.json, затем отдельно выполните --smaa-run.
```

Сохранённый импорт доступен и через существующие пункты 14/15/16. Создание нового
шаблона и запуск вручную описаны в [SMAA](smaa.md); [критерии Парето](pareto_csv.md)
сохраняют прежний формат. HTML SMAA теперь создаётся автоматически. В documents/ находятся именованные
HTML/CSV/JSON и индекс; режим smaa не создаёт отдельный отчёт Парето.

## Что CSV позволяет восстановить

Поддерживается нативный CSV UTF-8 с разделителем запятая: `name`, `smiles`,
столбцы `<target>_delta_g` и сопутствующие `<target>_ki`, `<target>_ki_formatted`,
`<target>_pki`. Произвольные таблицы SMILES или пересохранённые Excel-файлы другого
формата требуют отдельного преобразования; программа отклоняет неверную схему.
Положительные уникальные `row_id` сохраняются; при отсутствии назначаются по
порядку CSV-записей. Повторяющиеся названия допустимы. Нечисловые/бесконечные
оценки и дубли ID отклоняются, пустые оценки остаются пропусками.

Рекомендуется держать рядом файл `.csv.notes.json`, созданный DockScreen:
его контрольная сумма позволяет безопасно восстановить защищённые текстовые
ячейки. Несовпадающие метаданные — ошибка. Без него текст сохраняется буквально,
защитные апострофы не снимаются автоматически; это может влиять на SMILES.

CSV не содержит полного научного протокола и может содержать округлённые оценки.
Импорт явно помечает протокол как неизвестный; сведения о конфигурации, seed и
версиях Vina не выдумываются. Для максимально точного анализа предпочтителен
исходный сохранённый запуск с JSON. Докинг остаётся расчётной оценкой, а доли
SMAA — чувствительностью к выбранным предпочтениям, не вероятностью успеха.

Точная копия исходного CSV и sidecar сохраняется в `reports/import/`, рядом
`import_metadata.json` с хэшами и политикой восстановления. В `input.csv`
реконструированы только идентификаторы, имена и SMILES, это не исходный CSV
лигандов до докинга. ZIP включает эти снимки, обычные отчёты, Парето и завершённые
SMAA-папки. Ограничения импорта: CSV до 64 MiB, sidecar до 8 MiB, до 100000 строк,
64 мишеней и 100000 пар строка–мишень. SMAA принимает до 100000 исходных строк.

Предел исходных строк не гарантирует ранжирование 100000 допустимых кандидатов.
Проверка памяти SMAA остаётся отдельной: текущая плотная матрица рангов имеет
размер O(n²) по числу прошедших ограничения. Если её оценка превышает 256MiB,
расчёт отклоняется до выделения матрицы; сократите допустимый набор критериями.
Лимиты размера CSV и числа пар молекула–мишень сохраняются.

Автоматические HTML и схема имён документов описаны в [основном руководстве](../README_RU.md#html-и-понятные-имена-документов).
